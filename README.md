# Аналітична платформа для сервісу доставки квітів (Modern Data Stack)

## Суть проєкту

У проєкті реалізовано повний цикл сучасної аналітичної платформи (End-to-End ELT + BI) для сервісу доставки квітів:
- **Extract & Load (ЛР №1):** генерація транзакційних даних за допомогою Python та їх завантаження у сирий шар (`raw`) локального сховища даних PostgreSQL у Docker.
- **Transform & Data Quality:** моделювання та побудова аналітичних вітрин (`staging` $\rightarrow$ `analytics` / `marts`) через `dbt` з автоматичними тестами якості даних (`unique`, `not_null`, описаними у `schema.yml`).
- **Orchestration (ЛР №3):** автоматизація всього ELT-пайплайну та перевірок якості через Apache Airflow (DAG `ecommerce_elt_pipeline`).
- **BI & Data Governance (ЛР №4):** підключення Metabase для побудови аналітичних графіків і дашбордів, а також генерація документації з інтерактивним графом походження даних (*Data Lineage Graph*) у `dbt docs`.

### Опис таблиць (Доставка квітів)
- `clients` — інформація про клієнтів (ім'я, електронна пошта, дата реєстрації).
- `bouquets` — довідник букетів (назва, ціна, категорія).
- `florists` — список флористів (ім'я, досвід роботи).
- `deliveries` — таблиця доставок (зв'язок клієнта, букета та флориста, кількість, дата).
- `payments` — таблиця транзакцій/оплат (сума, зв'язок з доставкою та клієнтом).
- `reviews` — відгуки клієнтів про букети (оцінка, коментар).

## Використані технології

- **Python** — генерація синтетичних транзакційних даних (`Faker`), робота з табличними структурами (`Pandas`), завантаження даних у БД (`SQLAlchemy`, `psycopg2-binary`) та реалізація кроків пайплайну.
- **Docker & Docker Compose** — контейнеризація та запуск усіх сервісів стеку (`dwh_postgres`, `airflow`, `metabase`) в єдиній мережі.
- **PostgreSQL (`dwh_postgres`)** — сховище даних (DWH) зі схемами для сирих даних (`raw`), проміжних/очищених моделей (`staging`) та аналітичних вітрин (`analytics` / `marts`).
- **dbt (data build tool)** — SQL-трансформації моделей, тести якості даних (`unique`, `not_null`), генерація документації та інтерактивного *Data Lineage Graph*.
- **Apache Airflow** — оркестрація та послідовний запуск етапів ELT-пайплайну (`ecommerce_elt_pipeline`: завантаження сирих даних, трансформації `dbt` та запуск тестів якості).
- **Metabase** — BI-інструмент для підключення до `dwh_postgres`, об'єднання таблиць фактів і вимірів та візуалізації аналітичних метрик.

## Архітектура проєкту

```text
[Python (Faker + Pandas)]
        │  (SQLAlchemy)
        ▼
[PostgreSQL DWH: схема raw]
        │  (dbt run)
        ▼
[PostgreSQL DWH: staging ──► analytics / marts] ◄── [dbt test (Data Quality Gates)]
        │
        ├──► [Metabase BI] (Join вітрин, графіки, дашборди)
        └──► [dbt Docs]    (Документація та Data Lineage Graph)

* Оркестрація пайплайну виконується через Apache Airflow (DAG: ecommerce_elt_pipeline)
```

- **Python -> Docker PostgreSQL:** скрипт із `Faker` генерує транзакційні дані за сутностями доставки квітів, формує `DataFrame` у `Pandas` і через `SQLAlchemy` завантажує їх у схему `raw` бази `ecommerce_dwh`.
- **dbt + Apache Airflow:** DAG `ecommerce_elt_pipeline` автоматизує завантаження сирих даних, побудову моделей `dbt` (`staging` $\rightarrow$ `marts`) і перевірку тестів якості даних перед аналітичним використанням.
- **Metabase + dbt docs:** Metabase з'єднується з базою всередині Docker-мережі за ім'ям сервісу `dwh_postgres` для побудови графіків, а `dbt docs` формує документацію й *Data Lineage Graph* на основі моделей та описів у `schema.yml`.

## Усі інструкції запуску

### 1. Підготовка оточення та завантаження проєкту
1. Завантажте репозиторій проєкту на локальний ПК та встановіть **Docker** (разом із Docker Compose).
2. Якщо плануєте запускати скрипти або `dbt` локально на хості, встановіть **Python 3.9+** та потрібні бібліотеки:
   ```bash
   pip install pandas Faker sqlalchemy psycopg2-binary
   ```
   *(За потреби також активуйте віртуальне середовище `venv` та встановіть `dbt-postgres`.)*

### 2. Запуск сервісів у Docker
Перейдіть у кореневу папку проєкту та підніміть усі контейнери:
```bash
docker compose up -d
```
Перевірити стан сервісів і готовність бази `dwh_postgres` (`healthy`) можна командою:
```bash
docker compose ps
```

### 3. Завантаження даних та запуск оркестрації (ЛР №1 та ЛР №3)
- **Локальний запуск генератора даних (за потреби):**
  ```bash
  python data_generator.py
  ```
- **Запуск через Apache Airflow:**
  1. Відкрийте веб-інтерфейс Airflow за адресою `http://localhost:8080`.
  2. Увімкніть (Unpause) та запустіть DAG **`ecommerce_elt_pipeline`**.
  3. Перевірте у вкладці **Graph** / **Grid**, що задачі завантаження даних, `dbt run` і `dbt test` завершилися успішно.

### 4. Підключення та робота в Metabase (ЛР №4)
1. Відкрийте Metabase у браузері за адресою `http://localhost:3000`.
2. Додайте базу даних PostgreSQL із такими параметрами (використовується ім'я сервісу всередині Docker-мережі, а не `localhost`):
   - **Host:** `dwh_postgres`
   - **Port:** `5432`
   - **Database name:** `ecommerce_dwh`
   - **Username:** `admin`
   - **SSL:** вимкнено
3. Створіть аналітичні запити (*Questions*) та візуалізації на основі вітрин (зокрема об'єднання таблиці фактів із виміром клієнтів для виведення топ-5 клієнтів у вигляді стовпчастої діаграми *Bar chart*) і збережіть їх.

### 5. Генерація та перегляд документації `dbt` і Data Lineage (ЛР №4)
Перейдіть у папку `ecommerce_dbt` і виконайте:
```bash
cd ecommerce_dbt
dbt docs generate
dbt docs serve --port 8085
```
*(Параметр `--port 8085` використовується, щоб уникнути конфлікту порту `8080` у Windows; за потреби можна вказати інший вільний порт.)*

Після запуску відкрийте у браузері `http://localhost:8085` та натисніть **View Lineage Graph**, щоб переглянути граф залежностей, моделі, тести та описи зі `schema.yml`.
